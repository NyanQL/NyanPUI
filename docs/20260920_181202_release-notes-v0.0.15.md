# NyanPUI v0.0.15 リリースノート

v0.0.15では、既存APIをMCP Toolとして公開する機能と、API定義の多段include・ホットリロードを追加しました。MCP・OAuth・内部呼び出し・Push配信先にもAPIの前後チェックを適用します。JSON-RPCの型保持、HTTP応答後のPush、WebSocketのチェック・並行処理を改善し、ログ出力をNyan8・NyanQLと同じJSON形式に統一しています。

この文書は、NyanPUI本体・同梱サンプル・関連ドキュメントの変更をまとめています。

既存環境では、ファイル操作の相対パス、JSON-RPCの応答、ログ形式、前後チェックの適用範囲が変わります。更新前に「アップデート時の注意点」を確認してください。

## 新機能

### MCPサーバー

- `type: "mcp"` を追加し、既存の通常APIをMCP Toolとして公開できるようになりました。複数のMCPサーバー定義に対応します。
- Streamable HTTPとstdioに対応します。対応プロトコルバージョンは `2025-11-25` / `2025-06-18`、対応メソッドは `initialize`・`ping`・`tools/list`・`tools/call` です。
- Toolの入出力をJSON Schemaで検証し、`paramCheck` / `outCheck` のチェックスクリプトも実行します。Streamable HTTP・stdioともに、入力Schema検証 → `paramCheck` → 本体 → `outCheck` → 出力Schema検証の順です。出力Schema検証はスキーマがあり、応答の `status` が400未満の場合に行います。
- チェック拒否・不正なチェック結果・例外は、MCP Toolの `isError: true` 応答になります。MCP Tool経由の呼び出しでは、参照先APIのPushは実行しません。
- Streamable HTTPにOriginなどの検証、MCP専用のペイロード上限、同時実行制御、設定可能な接続元別レート制限を追加しました。
- `--mcp-server` でstdio専用モードを起動できます。このモードではHTTPサーバーやバックグラウンド処理、API定義のホットリロードを起動しません。

### OAuth連携のためのJavaScript拡張

- OAuthメタデータをGo側で生成・公開し、認可・トークン発行・クライアント登録・アクセストークン検証をJavaScriptへ委譲する仕組みを追加しました。
- 認証、PKCE、認可コードの消費、トークンの発行・検証、ユーザー管理はアプリケーション側のJavaScriptで実装します。
- OAuth用の状態ファイル操作、乱数・SHA-256・Base64・Argon2idの補助関数を追加しました。Argon2idは将来の生成設定変更時にも既存ハッシュの検証設定を保持できる構造にしています。

### API定義の分割とホットリロード

- `type: "include"` による多段includeを追加しました。API定義を複数ファイルに分割し、マウント名を付けて読み込めます。
- 最上位のAPI定義とinclude先の変更を検出し、通常API、静的ファイル配信、スケジュール、WebSocketクライアントの定義へ反映します。
- ホットリロードは既定で有効、確認間隔は1秒です。不正な変更を検出した場合は、直前の正常な定義を維持します。
- `/nyan/{API名}` からAPIの詳細と入出力スキーマを取得できるようになりました。`nyanInputSchema` / `nyanOutputSchema` に加え、従来の `nyanAcceptedParams` も入力スキーマとして扱います。

### JavaScript補助関数

- `nyanGetRequestHeaders()`：リクエストヘッダーを取得します。WebSocket接続時のOrigin判定などに使用できます。
- `nyanSaveFile()` / `nyanDeleteFile()`：ファイルを保存・削除します。保存は同じディレクトリの一時ファイルへ書き込んでから置き換えます。
- `nyanRemoveItem()`：プロセス内の共有ストレージから指定キーを削除します。

## 改善・修正

### 実行前・出力前チェック

- 設定した `paramCheck` / `outCheck` を、通常HTTP・JSON-RPC・public・WebSocketに加え、MCP Tool・OAuth用API・`nyanCallMe()` の呼び出し先・Push配信先でも実行します。成功条件は `success: true` かつ `status: 200` です。実行前の拒否では本体を実行せず、出力前の拒否では本体の結果を返却・配信しません。
- OAuth用APIでは、認可・トークン・登録に加え、Goが生成するメタデータと `verifyAccess` にも前後チェックを適用します。OAuth用HTTP endpointの拒否は通常APIと同じチェック結果JSONとHTTPステータスで返します。`verifyAccess` のチェック拒否は認証失敗としてHTTP 401を返し、Toolを実行しません。メタデータへの `OPTIONS` はチェック対象外です。
- `nyanCallMe()` のチェック拒否は、呼び出し元のJavaScriptで `try` / `catch` できる例外になります。チェック成功時の戻り値の型と、JSON文字列を自動でオブジェクト化する挙動は維持します。
- Pushは、配信先の前後チェックを通過した内容だけを配信します。配信先で拒否された場合も、配信元の成功応答は変更しません。
- `type: "schedule"` と `type: "ws_client"` 自身のバックグラウンド実行はチェック対象外です。ただし、そのスクリプトから `nyanCallMe()` で通常APIを呼び出した場合は、呼び出し先のチェックを実行します。
- `nyan_mode=checkOnly` では実行前チェックだけを行い、本体・`outCheck`・Push配信を実行しません。MCPの `verifyAccess` では、チェックだけの成功を認証成功と扱わずHTTP 401で停止します。本体が例外などで失敗し結果を取得できなかった場合も、`outCheck` は実行しません。

### JSON-RPC・HTTP・WebSocket

- JSON-RPCの `result` でオブジェクト・配列・数値・真偽値の型を保持するようになりました。文字列はそのまま返し、`null` / `undefined` は `result: null` として返します。
- JSON-RPCでも `outCheck` を実行します。`paramCheck` / `outCheck` の拒否はJSON-RPCエラー `-32000` とし、元のチェック結果を `error.data` に格納します。
- `/nyan-rpc` の呼び出し先を、スクリプトを持つ通常APIに限定しました。MCPのOAuth処理用APIも呼び出し対象から除外します。
- 通常HTTPでは、文字列・オブジェクト・空応答・HTMLのみのいずれも、チェック通過後の応答ステータスが200〜399なら設定されたPushを実行します。4xx/5xx、チェック拒否、処理失敗、`checkOnly` では実行しません。
- WebSocket接続確立前に `paramCheck` を実行し、受信したAPI要求にも入出力チェックを適用します。
- 並行リクエスト間でCookieや内部呼び出しのリクエスト情報が混在する問題と、WebSocketの応答・Pushが同時に書き込まれる問題を修正しました。
- WebSocketクライアントの接続成功後に再接続待ち時間を1秒へ戻します。ホットリロードでscriptやdescriptionだけが変わった場合は接続を維持します。

### ログ・設定管理

- ログを1行1件のJSON形式に統一しました。`log.Level` で `debug` / `info` / `warn` / `error` を指定できます。
- `log.EnableLogging: true` ではファイルへの追記とローテーション、`false` では標準エラー出力を使用します。
- エラー詳細とJavaScriptの `console.log` はdebug時のみ出力します。接続URLに含まれる資格情報・パス・クエリなどのログへの露出も抑制しました。
- includeの循環参照、API名の衝突、重複JSONキー、不正なバックグラウンド処理の定義を検証します。
- OAuth状態ファイルの一覧からNyanPUIが作成する一時ファイルだけを除外し、ホットリロード後に不要になったMCP同時実行制御のデータを回収するようにしました。

## 削除したサンプル

- ワイヤーフレーム用CSS `html/css/wf_style.css` と、サンプルHTML `html/wf_html.html` を削除しました。
- 同梱の `api.json` から `/wf` 用のAPI定義を削除しました。
- READMEからワイヤーフレームデザインプレビューの説明を削除しました。

## アップデート時の注意点

| 対象 | 変更内容と対応 |
| --- | --- |
| ファイル操作の相対パス | `nyanGetFile` / `nyanSaveFile` / `nyanDeleteFile` / `nyanReadFileB64` は、最上位のAPI定義ファイルがあるディレクトリを基準にします。従来の `nyanGetFile` の実行ファイル基準、`nyanReadFileB64` のカレントディレクトリ基準を利用していた場合は、相対パスを調整するか絶対パスを指定してください。 |
| API定義内のパス | script・HTML・チェック・public・includeの相対パスは、それぞれを記述したAPI定義ファイルの場所が基準です。JavaScript補助関数の相対パスとは基準が異なります。 |
| JSON-RPCの結果 | JavaScriptが返した値の型を保持します。オブジェクトなどを直接返すAPIでは、クライアント側の文字列前提の処理を見直してください。`JSON.stringify(...)` を返すAPIの結果は引き続き文字列です。 |
| JSON-RPCとHTTP応答用オブジェクト | `{status, headers, contentType, body}` を返す場合、オブジェクト全体が `result` になります。`body` の抽出や、status・headersのHTTP応答への適用は行いません。 |
| JSON-RPCのチェック拒否 | HTTP 200でJSON-RPCエラーを返します。HTTPステータスだけでなく `error` / `error.data` を確認してください。公開対象外のAPIは `-32601` になります。 |
| 前後チェックの適用範囲 | MCP・OAuth・`nyanCallMe()`・Push配信先でも、参照先APIに設定済みのチェックを実行します。従来は通過していた呼び出しが拒否される場合があります。各経路から渡されるパラメータとチェック条件を確認してください。 |
| MCP用のチェックファイル | スキーマ宣言だけではチェックに成功しません。通常APIと同じ `{success, status, result}` を返す実装が必要です。成功時は `success: true` かつ `status: 200` としてください。MCPで `checkOnly` を使用し、入力Schemaでプロパティを制限している場合は `nyan_mode` も許可してください。 |
| ホットリロード | `APIHotReload` を省略した場合も有効です。無効にする場合は `APIHotReload.Enabled: false` を指定してください。JavaScriptは実行ごとに読み込むため、この設定を無効にしてもスクリプトの変更は次回実行に反映されます。 |
| 起動時の検証 | 不正なschedule / ws_client定義も起動エラーになります。更新前に使用中のAPI定義を確認してください。 |
| ログ収集 | JSON形式に合わせて収集・解析設定を更新してください。`EnableLogging: false` はログ無効化ではなく標準エラー出力です。エラー詳細や `console.log` の確認には `Level: "debug"` を指定します。 |
| API一覧・予約名 | `/nyan` の一覧からpublic / ws_clientを除外します。`mcp_principal` / `mcp_tool` は予約パラメータとなり、外部リクエストからの指定を拒否します。 |
| ワイヤーフレームサンプル | 同梱サンプルからCSS・HTML・`/wf` のAPI定義を削除しました。既存ページで `wf_style.css` や `/wf` へのリンクを利用している場合は、スタイルや参照先を更新してください。 |

MCP/OAuthの設定方法とJavaScript hookの仕様はREADMEに記載しています。認証・トークン検証・ユーザー管理は、利用するアプリケーション側で実装します。

API定義とJavaScriptは信頼できる管理者が配置する前提です。実行ユーザーのOS権限でコマンド実行やファイル操作を行えるため、定義・スクリプトと親ディレクトリの書き込み権限を管理してください。ファイル操作の相対パスの基準は、アクセス可能な範囲を制限するものではありません。

`config.json` の `version` はアプリケーション自身のバージョンです。NyanPUI本体のバージョンに合わせて変更する必要はありません。

## 依存関係・検証

- Go指定を `1.26.6` に更新しました。
- `golang.org/x/crypto` を `v0.56.0` に更新し、Dependabotから要求された `v0.52.0` 以上に対応しました。`x/net`・`x/sys`・`x/text`・protobufなども更新しています。
- JSON Schema検証ライブラリを追加し、未使用のv8go依存を削除しました。
- OAuth用API、MCP ToolのHTTP／stdio、`nyanCallMe()`、Push配信先の前後チェックについて、拒否時の処理停止、`checkOnly`、戻り値や配信内容の維持を確認する回帰テストを追加しました。
- API定義の更新、JSON-RPC、MCP、OAuth、WebSocket、Push、ファイル操作、ログなどの回帰テストを拡充しました。Go `1.26.6` / macOS arm64で、race detector付きテスト、`go vet`、ビルド、`go mod verify` の成功を確認しています。

# NyanPUI v0.0.16 リリースノート

v0.0.16では、HTTP・WebSocketの受信サイズ制限とHTTPタイムアウトを追加しました。APIの前後チェックをMCP・OAuth・内部呼び出し・Push配信先へ広げ、チェック結果、`checkOnly`、Pushの実行条件を統一しています。共通ファイル保存関数の追加、コマンド実行結果のオブジェクト化、Goと依存ライブラリの更新も含みます。

既存環境では、チェックの成功条件、実行モードの指定、受信上限、`nyanHostExec()` の戻り値に注意が必要です。更新前に「アップデート時の注意点」を確認してください。

この文書は、`v0.0.15` タグから `88f98ab` までのコミット済み変更を対象とします。

## 新機能

### HTTP・WebSocketの受信サイズ制限

`config.json` に `receiveLimits` を追加しました。

```json
{
  "receiveLimits": {
    "httpBodyBytes": "20MB",
    "webSocketMessageBytes": "20MB"
  }
}
```

| 設定 | 対象 | 既定値 |
| --- | --- | --- |
| `httpBodyBytes` | 通常API・JSON-RPC・MCP/OAuth・静的配信などのHTTPリクエスト本文全体 | 20 MiB |
| `webSocketMessageBytes` | WebSocketサーバーと `ws_client` が受信する1メッセージ全体 | 20 MiB |

- `B`・`KB`・`MB`・`GB`、`KiB`・`MiB`・`GiB`、整数のバイト数を指定できます。単位は1024倍で換算し、`20MB` は20,971,520バイトです。
- 未指定・0は既定値を使用します。負数・小数・不明な単位・範囲外の値は設定エラーです。
- 上限と同じサイズは受理し、超過時はHTTP 413、WebSocketのclose code 1009で拒否します。`Content-Length` がない本文や、複数フレームに分割されたWebSocketメッセージも制限します。
- multipartは添付ファイルだけでなく境界・フォーム項目を含む本文全体が対象です。超過した内容はJavaScriptへ渡しません。
- MCP/OAuthのHTTP本文に適用していた固定1 MiB上限も、この設定へ置き換わります。MCPのstdioメッセージ、出力サイズ、OAuth状態ファイルなどの既存上限は別の制限です。

### HTTP通信のタイムアウト

`config.json` に `httpTimeouts` を追加しました。

```json
{
  "httpTimeouts": {
    "readHeaderTimeout": "30s",
    "readTimeout": "20m",
    "writeTimeout": "30m",
    "idleTimeout": "5m"
  }
}
```

| 設定 | 対象 | 既定値 |
| --- | --- | --- |
| `readHeaderTimeout` | HTTPヘッダーの受信 | 30秒 |
| `readTimeout` | 本文を含むHTTPリクエスト全体の受信 | 20分 |
| `writeTimeout` | HTTP応答の書き込み期限 | 30分 |
| `idleTimeout` | Keep-Aliveで次のリクエストを待つ時間 | 5分 |

未指定・`null`・`"0s"` は既定値を使い、無制限にはなりません。受信期限は受信全体に対して適用され、無通信時間だけの制限ではありません。通信タイムアウトは実行中のJavaScriptやDB処理を強制終了するものではなく、WebSocketへ切り替えた後はHTTPの期限を引き継ぎません。`receiveLimits` と `httpTimeouts` の変更を反映するには再起動が必要です。

### 共通ファイル保存関数

NyanQL・Nyan8と同じ引数順・戻り値の保存関数を追加しました。

```javascript
nyanWriteTextFile("./files/message.txt", "こんにちは");
nyanWriteBase64File("./files/message.bin", "aGVsbG8=");
```

- `nyanWriteTextFile(path, text)` はUTF-8のテキスト、`nyanWriteBase64File(path, base64)` は標準Base64をデコードしたバイト列を保存します。
- 成功時は `true`、失敗時はJavaScript例外です。引数は文字列を必須とし、空の内容は空ファイルとして保存できます。
- 相対パスは最上位のAPI定義ファイルのディレクトリが基準です。親ディレクトリを作成し、同じディレクトリの一時ファイルへ書き込んでから置き換えます。Unix系では親ディレクトリを0750、保存ファイルを0600で作成します。
- 既存の `nyanSaveFile()` は引数・戻り値を維持します。

## 改善・修正

### 前後チェックと実行モード

- `paramCheck` / `outCheck` を、MCP Tool、OAuth用API、`nyanCallMe()` の呼び出し先、Push配信先にも適用します。入力チェック拒否時は本体を実行せず、出力チェック拒否時は本体の結果を返却・配信しません。
- チェック結果の `status` は200〜599の整数を必須とし、小数や1xxなどを拒否します。その形式検証を通過した後の成功・拒否は、真偽値の `success` で判定します。
- 成功した `outCheck` は本体のステータス・本文・ヘッダーを保持します。本体が201、チェックが `success: true, status: 200` の場合、最終HTTP応答は201です。publicのRange・HEAD・条件付き要求も維持します。
- `nyan_mode` は省略・空文字列で通常実行、正確な文字列 `"checkOnly"` で入力チェックのみを実行します。それ以外の値や重複指定を拒否し、`checkOnly` には `paramCheck` を必須としました。
- `checkOnly` では本体・`outCheck`・Pushを実行しません。入力チェック自身の副作用を取り消す機能ではありません。
- `schedule` / `ws_client` 自身のバックグラウンド実行は前後チェックの対象外ですが、そこから `nyanCallMe()` で呼ぶ通常APIにはチェックを適用します。

### MCP・OAuth

- MCPのHTTP・stdioで、入力JSON Schema検証 → `paramCheck` → 本体 → `outCheck` → 出力JSON Schema検証の順に処理します。出力Schema検証は、スキーマがあり応答の `status` が400未満の場合に行います。
- MCPの結果の最上位に真偽値の `success: false` がある場合、業務上の失敗として `isError: true` を返します。元の結果は `content` と `structuredContent` に保持します。構造化HTTP応答ではJSON本文の最上位を判定します。
- MCPの入力スキーマに `nyan_mode` を自動追加します。最上位のローカル `$ref` の連鎖にも対応し、同じ定義を使う子オブジェクトの制約やアンカーを維持します。`$id` を持つ埋め込みリソース、Draft-04の `id` を持つ定義、`allOf` などの合成先は自動追加の対象外です。
- OAuthの認可・トークン・登録・メタデータ・`verifyAccess` に前後チェックを適用します。`verifyAccess` のチェック拒否や例外はHTTP 401でToolの実行を止めます。呼び出し元が `checkOnly` でも、認証本体を省略しません。
- OAuthで設定したCookieは、内部呼び出しによる設定も含めて一旦保留し、チェックと本体処理が通過した場合に応答へ反映します。出力チェック拒否時に本体が設定したCookieを送信する問題を防ぎます。
- OAuthの不正なJSON・フォーム・本文読取失敗をチェック前に拒否し、`OPTIONS` ではチェックや本体を実行しません。

### Push・WebSocket

- 通常HTTPに加え、JSON-RPC、`nyanCallMe()`、MCP Toolの参照先APIでも、成功した実行に設定されたPushを実行します。内部呼び出しとMCPでは結果を返す前にPush処理を行います。
- Push元の本体ステータスが200〜399であることに加え、JSON結果の最上位の `success: false` や数値の `status` も確認します。チェック拒否、業務上の失敗、実行・変換エラー、`checkOnly` ではPushを抑止します。
- MCPでは結果のJSON・出力スキーマ・応答全体のサイズを検証してからPushを実行し、送信できない結果による通知を防ぎます。
- Push先へ渡す `api` を配信先のAPI名に統一します。Push先での拒否・例外は配信元の成功応答を変更せず、Push先の `nyanSetCookie()` も配信元の応答へ影響しません。
- 切断・送信失敗したWebSocket接続だけを登録から除去し、同じAPIを購読する他の接続への配信を継続します。
- WebSocketのAPI要求に含まれる `null`・数値・真偽値・配列・オブジェクトの値を拒否します。既存の文字列形式のメッセージは維持します。

### HTTP入力・JSON-RPC・接続管理

- 通常HTTPのクエリ・フォームで同じ項目を複数指定した場合、順序を維持した文字列配列として渡します。同名項目は本文をクエリより優先し、本文の空文字列や `null` も保持します。
- 空でないJSON本文を1文書として検証し、連結されたJSONや末尾の余分なデータをHTTP 400で拒否します。通常HTTPでは空本文・空白だけの本文・本文全体の `null` は、追加パラメータなしとして扱います。
- JSON-RPCの配列結果を文字列変換せず、`outCheck` へJSON配列を表す本文文字列として渡します。要素内の `success: false` などだけを理由にPushを止める誤判定や、要素の `toString` 呼び出しを防ぎます。
- JSON-RPCの通常結果は `outCheck` の有無によらずHTTP 200で返します。`checkOnly` の成功結果が204・205・304の場合は、外側のHTTPステータスだけ200に置き換え、結果内の `status` と応答本文を保持します。
- サイズ超過、MCPのレート・同時実行制限、MCP/OAuthのヘッダー検証、CORSの事前要求などで本文の受信完了前に応答する際、未受信の本文を待ち続けないようにしました。未読本文があるHTTP/1接続は終了し、HTTP/2では他のリクエストに接続を再利用できます。
- WebSocketへの切り替え後に、接続時のHTTP本文バッファを保持し続ける問題を修正しました。

### JavaScript補助関数・Argon2id

- `nyanHostExec()` はJSON文字列からJavaScriptオブジェクトへ戻り値を変更しました。`success`・`exit_code`・`stdout`・`stderr` を直接参照できます。非0終了も同じ形式で返し、引数省略やシェル起動失敗は例外になります。
- `nyanGetAPI(url)` は認証引数を省略してGETを実行できるようになりました。URL引数なしは `TypeError` になります。通信失敗時は従来どおりログを記録して空文字列を返します。
- Argon2idの検証を、保存されたPHC文字列の設定に基づく範囲検証へ拡張しました。メモリ64〜256 MiB、反復3〜10回、並列度1〜16、ソルト・ハッシュ長16〜64バイトを受け付けます。不正な形式や範囲外の入力は計算前に拒否します。
- Argon2idの生成・検証は、合わせて1プロセス内の同時2件までに制限します。新規生成の標準設定 `m=65536,t=3,p=2` と既存の標準ハッシュは維持します。

## アップデート時の注意点

| 対象 | 確認・対応内容 |
| --- | --- |
| チェックでの拒否 | `success: true, status: 403` は通過します。拒否する場合は必ず `success: false` を返してください。`status` は成功・拒否とも200〜599の整数が必要です。JSON文字列で返す場合の `200.0` や `2e2` も拒否します。 |
| MCP・OAuth・内部呼び出し・Push先 | 設定済みのチェックが実行されるようになります。MCP用ファイルがスキーマ宣言だけの場合は、最後の評価値として `({success: true, status: 200, result: {}});` などのチェック結果も返してください。 |
| `nyan_mode` | `CHECKONLY` や空白付きの指定は `checkOnly` に、通常実行用の `normal` 等は省略または空文字列に変更してください。`checkOnly` を使うAPIには `paramCheck` を設定してください。未設定時のエラー形式は呼び出し経路ごとに異なります。 |
| 既存の大容量・長時間リクエスト | 設定を省略した既存環境にも受信サイズとタイムアウトの既定値が適用されます。必要に応じて `receiveLimits` / `httpTimeouts` を調整し、サービスを再起動してください。0は無制限を意味しません。 |
| クエリ・フォームの重複項目 | 複数指定した値は配列になります。常に単一の文字列を想定していたチェックや本体を確認してください。同名のクエリと本文では本文が優先されます。 |
| `nyanHostExec()` | `JSON.parse(nyanHostExec(command))` を `nyanHostExec(command)` に変更してください。文字列が必要な場合は `JSON.stringify()` を使います。通常HTTPのJSON本文として返す場合は `{status: 200, contentType: "application/json", body: result}` で包んでください。 |
| MCPの業務結果・入力スキーマ | `success: false` を業務上の失敗として扱います。`nyan_mode` の自動追加対象外となる `$id`・Draft-04の `id`・合成スキーマを使う場合は、入力全体を検証する各スキーマで `nyan_mode` を明示的に許可してください。 |
| Pushの副作用 | 内部呼び出し・MCPからもPush先が実行されます。購読者がいなくても実行され、親と子のAPIにそれぞれPushがあれば独立して実行します。子のPushは後から親が失敗しても取り消されません。stdioから別プロセスのHTTPサーバーへ中継する機能ではありません。 |
| Argon2id | 外部から取り込んだハッシュは、許可範囲と正規のPHC表記を確認してください。自動再ハッシュやパスワード再設定は行いません。 |

`outCheck` の `nyan_output.body` / `nyan_output_body` は文字列です。JSONのオブジェクトや配列として検査する場合は `JSON.parse()` で解析してください。チェックやPushによる実行済みのファイル書き込みなどを取り消す機能はありません。
